	For starters the client summary and requirements. Who was the client? The client was called Artemis Financial. This was a financial servicing company that was looking to modernize and secure their software applications. The issue? The company needed to protect sensitive financial data and ensure secure communication channel. This would require identifying existing vulnerabilities in their software architecture and updating the application to meet modern security standards. This specifically added secure encryption practices and protecting data in transit.
	Now for the vulnerability assessment reflection. What went well is the conducting the initial vulnerability assessment allowed for a clear, structured overview of out-of-date dependencies and potential vectors of attack. Identifying these flaws early made it straightforward to map out exactly which parts of the codebase required refactoring. As for the importance of secure coding, coding securely from the ground up protects both corporate infrastructure and user trust. For a financial client, software security mitigates the risk of catastrophic data breaches, ensures regulatory compliance, and directly protects the organizations financial health and reputation.  Lastly, the challenges and helpful aspects. This includes the most helpful part of the assessment was using automate dependency check tools, which pinpointed precise CVEs (Common Vulnerability and Expositions). The most challenging aspect was verifying false positives and determining which dependency updates would break existing functionality versus which ones were safe to upgrade immediately.
	As for the defensive practices and future planning. To start, the best move is to increase the layers of security. Layered security by refactoring code to implement strong cryptographic algorithms (Like, SHA-256 for data integrity) and configuring secure transport protocols, such as HTTPS. The next best move is in the future mitigation techniques. In the future projects, I plan to integrate static application security testing tools, in order to directly into the CI/CD pipeline, ensuring that the code is continuously scanned for vulnerabilities before it is ever deployed.
	Next, we are going to talk about the verification and testing. First we have to ensure the functionality and security. To ensure the refactored code remained functional while becoming more secure, rigorous unit testing was utilized alongside verification of the secure endpoints. Next, we have to check for new vulnerabilities, this is done by running a secondary dependency check and vulnerability scan were executed. This verified that updating libraries and changing the code logic did not inadvertently introduce new security regressions or break existing software dependencies.
	Finally, we are going to discuss the tools, resources, and career impacts. For starters, resources and tools used, the key tools included the Maven dependency check plugin for vulnerability identification, Java’s built-in security libraries for cryptography, and standard IDE testing frameworks to verify application stability. Last, we are going to showcase value to the employers. This project serves as a tangible example of a security first mindset. It demonstrates to future employers an ability to not only write functional code, but to systematically audit an existing codebase, identify security risks, remediate vulnerabilities, and implement industry-standard cryptographic solutions.
